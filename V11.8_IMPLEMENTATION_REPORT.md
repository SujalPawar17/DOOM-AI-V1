### Acceptance-phase narrow fix (GAP-03 completion)

During final acceptance I found that non-plan, planning-failure and cost-blocked cycles still carried a random `execution_id` (from the V11.1 placeholder `_result`) in the cycle output. Nothing was persisted or audited, but it was still a fabricated execution ID.
The orchestrator now reports `executed: False` and an empty `execution_id` whenever nothing was handed to the V8 executor. Real executions keep the executor's ID. `execution_layer.py` (the V11.1 contract) is unchanged. Test assertions were added in A, B, C and D. See `V11.8_FINAL_ACCEPTANCE_REPORT.md` for the re-run results.

### Additional defect discovered: Cost Guard blocked every plan (GAP-09)

Stage 8 sent one generic `ResourceRequest(OTHER, provider="local", capability="compute")`. That provider is unattested, so the **real** Cost Guard returned `UNKNOWN_PROVIDER_BLOCKED` for **every** plan, and no plan could execute end to end. (V11.7 tests mock `decision`, so they never saw this.)

**Fix (fail-closed, no Cost Guard or registry change):** one request per distinct step capability, mapped onto **existing** attestations:

| Capability | Request |
|---|---|
| `conversation` | LLM/`ollama`@localhost |
| `system_read`, `filesystem` | OTHER/`local_filesystem` |
| `memory_read`, `memory_write` | DATABASE/`postgres`@localhost |
| `computer`, `sequence`, `verification` | VISION/`local_uia` |
| `browser`, `world_act` | Unmapped → unattested → **blocked** |

Every request must be ALLOW. If a plan has no inspectable steps, the orchestrator falls back to the original generic request, which is still blocked. `cost_guard_check.checked` now reports whether the guard ran.

## 5. Safety validation

- **No fabrication:** non-plan, planning-failure, cost-blocked and pending cycles never claim execution or create experiences. The synthetic cost-blocked result has `plan=None`, so V8 `_audit_execution` writes no audit record.
- **Cost Guard before execution:** asserted with an `execute_plan` spy and adapter spies (D, H).
- **Authorization enforced:** the protected action never runs without the claimed hash. Claims are single-use, and tamper detection is preserved (E, H).
- **Verification enforced:** derived only from executor facts (C, F). The V11.7 "FAILED verification_state ⇒ not success" behaviour is preserved.
- **Caller-context hardening:**
  - Lowest precedence: caller keys never override source keys.
  - Identity/`auth*`/`approval*`/`authorized*`/`cost*`/`owner*`/`session*`/`pending*` keys are rejected.
  - Secret-named keys are rejected, and values pass through the existing V10 `_apply_privacy_protection`.
  - Only JSON-safe scalars are accepted. Previously a non-JSON value would crash `_generate_hash` and fail the whole cycle.
  - At most 16 caller keys, independent of fused size, so monitoring metadata isn't dropped when sources are large.
- **Owner isolation:** the cross-owner experience check (G) and owner-mismatch execution check (F) both pass.
- **Browser automation:** still OFF; browser steps are additionally Cost-Guard-blocked. **STT:** untouched. **V9:** no file changed, no engine/audio constructed.

## 8. Known limitations

1. **Non-plan responses are the V10.4 reasoning summary, not a synthesized answer.** For example, "What is the capital of France?" returns a reasoning summary, not "Paris". The V11 orchestrator has no answer-generation stage; adding one (local LLM) is outside V11.8 scope. V10.4 summaries can contain internal phrasing (e.g. "Goal requires creating artifact 'file.txt' on disk.").
2. **The goal lifecycle is never auto-completed by V11** (by design, §3 GAP-07). The registry is disabled by default (`PROACTIVE_V826_GOAL_REGISTRY_ENABLED`), so production reports `ACTIVE_GOAL_UNAVAILABLE`.
3. **`world_act` plans are always Cost-Guard-blocked** (no attestation exists). Enabling them needs an explicit Cost Guard attestation decision. `system_read` is mapped to the `local_filesystem` attestation (closest existing local, read-only attestation).
4. **First-cycle latency:** the first Stage 13 call imports the `core.voice` package (≈2.6 s once). Later cycles take ≈0–1 ms.
5. **V9 classification of reasoning-summary text can be surprising** (e.g. "Hello DOOM" → `CRITICAL`, because the summary contains "immediately"). This is V9's deterministic classifier output and wasn't changed.
6. Scenario B with the real V10 pipeline yields `EXECUTE_TOOL` with no plan, so the real-pipeline goal path is not executed. Plan execution is covered in C/E/F with explicit validated `GoalPlan`s.
