# DOOM V12.5 — Controlled Computer Interaction: Implementation Report

**Date:** 2026-10-04 · **Branch:** DOOM-V10 · **Base:** `95e2780` (`V12.4-FREEZE`)

## 1. Architecture

```
ComputerIntent -> plan(): perception (observe) -> target resolution -> safety refusals -> ComputerActionPlan
               -> execute(plan, trusted identity, authorized_hash?):
                    identity -> emergency stop -> Cost Guard (VISION/local_uia) -> claimed single-use
                    plan-bound approval -> re-observe -> browser check -> stale-observation check
                    -> action (bounded timeout) -> post-observation -> verification -> rollback (TYPE)
                    -> audit (owner-scoped, bounded)
```

## 2. Action catalog

| Action | Capability | Risk | Authorization | Expected result | Verification | Timeout | Failure behaviour |
|---|---|---|---|---|---|---|---|
| OBSERVE | computer_observe | LOW | no | fresh snapshot | observation hash present | 2 s | report; nothing changed |
| READ_VALUE | computer_observe | LOW | no | visible value of a non-sensitive element | element exists, not sensitive | 2 s | report; nothing changed |
| CLICK | computer_act | MEDIUM | **yes** | declared label reaches the expected value | post-action snapshot | 3 s | no retry; report (clicks cannot be undone) |
| TYPE | computer_act | MEDIUM | **yes** | input equals the typed text | post-action value | 3 s | no retry; **restore previous value**, then report |

## 3. Hard safety rules

- **Browser windows refused** at plan and execute time. Browser automation stays OFF.
- **Password and sensitive fields** (password, PIN, OTP, token, API key, card, SSN…) are never typed into or read. No credential extraction or cookie/CSRF handling exists anywhere in this layer.
- **Targets** must resolve uniquely and be visible and enabled. There's no guessing and no hidden interaction.
- **TYPE input** is bounded to 1–256 printable characters, with no control characters, key combinations or free-form injection. CLICK must declare an observable expectation.
- **Approvals** are bound to the exact plan hash (target, text, expectation and precondition observation). They must be claimed to be redeemed, are single-use, and expire under the TTL. Knowing the hash is not authorization (tested).
- **Stale observation:** if the screen changed between planning and execution, the action is refused.
- **Emergency stop** blocks every plan and execution until cleared.
- **Bounded execution:** a single worker thread with per-action timeouts.

## 4. Real UI integration

As required, deterministic **simulated UI tests come first**. `SimulatedUIBackend` mirrors the Safe Test Window contract (DOOM_TEST_BUTTON READY→CLICKED, DOOM_TEST_INPUT) with fault injection.

Real desktop actions remain on the existing authorized V8 computer path (V8 executor + `orchestration.authorization` + UIA kernel; exercised by V11.8 Scenario E with mocked sessions). The `UIBackend` interface is the integration point for a future explicitly approved live backend. **This layer does not drive the real desktop**, and no UI-automation library is imported (asserted by test).
