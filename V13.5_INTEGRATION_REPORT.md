### Defect found and fixed during V13.5

In the first full serial regression, flow G failed: "Your profile already has that". The earlier passing run had confirmed the preference into the **real durable V8.27 profile store** (local PostgreSQL) for the test owner `test_owner_v118`, so the test was not hermetic.

- **Fix:** the test base now uses the store's built-in test mode (`use_test_user_model_store(True)`) and resets pending profile confirmations.
- **Cleanup:** the single row V13 had created (`test_owner_v118 / preference / prefer_language`, created 2026-10-05 11:42) was retired through the store's own `forget_profile_entry` (ACTIVE → SUPERSEDED, no hard delete).
- **Verification:** two further runs passed, and the store showed no new rows.
