## 2. Implementation — `core/v13/real_computer.py`

`RealUIABackend` is a `UIBackend` for the **unchanged** V12.5 controller. It adds gates on top of every V12.5 safety property:

1. **Explicit enablement:** `DOOM_V13_REAL_COMPUTER=1`; otherwise construction raises `RealComputerGated`.
2. **Exact window allowlist:** `FindWindowW(class, title)` must match exactly (default `DoomSafeTestWindow` / "DOOM Safe Test Window"). Other windows are unreachable.
3. **Application controls only:** elements need a stable automation id, so window chrome (Minimize, Maximize, Close) is excluded. This was found during live observation and fixed.
4. **Semantic patterns only:** `Invoke()` and `ValuePattern.SetValue()`. No mouse, keyboard, `SetForegroundWindow`, coordinates or shell (AST/string-asserted).
5. Status labels are mapped via a per-window alias (`2002` → `Status`), so CLICK verification reads the real post-action state.

`SafeTestWindowProcess` launches and closes the harmless fixture (with `WM_CLOSE`, plus kill as fallback). No fixture processes remained after the runs (`tasklist` verified).

## 5. Decision: real computer interaction remains gated

It is safe **for allowlisted windows** under the existing architecture. It is **not** enabled for general desktop use. Broadening beyond the Safe Test Window would need:
- an owner-approved allowlist per application;
- a UX for approvals (same blocker as V13.1);
- supervised live trials.

The browser stays OFF.
