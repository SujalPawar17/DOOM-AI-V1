# DOOM V12.7 — Proactive Personal Assistant: Implementation Report

**Date:** 2026-10-04 · **Branch:** DOOM-V10 · **Base:** `6ed5189` (`V12.6-FREEZE`)

## 1. Architecture

```
signals: detected changes (V12.6 runtime) | active goal (V8.26 registry) |
         learned knowledge (V12.2: failure patterns, habits)
  -> detectors -> candidate suggestions -> cooldown + per-cycle bound + quiet mode
  -> classify_action(declared ActionSpec) -> policy by action class
  -> inbox (owner/session-scoped, bounded)
  -> respond(suggestion, trusted identity, accept, confirm_irreversible)
  -> V12.3 IntegrationGateway (Cost Guard, claimed approval, bounded execution, verification, experience)
```

| Detector | Suggestion | Class |
|---|---|---|
| Detected change (runtime event) | "Heads up: …" | INFORMATIONAL |
| Active goal inactive > 3 days | reminder to pick it up | INFORMATIONAL |
| First unfinished goal step | next action | INFORMATIONAL |
| Learned unreliable workflow | stalled-workflow help offer | INFORMATIONAL |
| Learned morning habit | prepare information (proposes `git.status`) | LOW_RISK |

## 2. Action-class policy (enforced)

| Class | Derived from the declared ActionSpec | Behaviour |
|---|---|---|
| INFORMATIONAL | no action | delivered automatically |
| LOW_RISK | LOW risk, non-mutating | auto-executed only when `AssistantPolicy.auto_low_risk=True`; otherwise proposed |
| MEDIUM_RISK | MEDIUM risk or mutating | user acceptance → gateway approval → claim → execute (auto never applies) |
| HIGH_RISK | HIGH+ risk | explicit authorization always; auto never applies |
| IRREVERSIBLE | mutating and `reversible=False` | explicit authorization + `confirm_irreversible=True` + **verified** result required, otherwise FAILED |

- Undeclared actions are never proposed.
- Responses require the suggestion's own owner and session.
- A suggestion executes at most once.
- Quiet mode delivers informational items only.

## 3. Changes to earlier V12 phases (documented)

- **V12.3 `ActionSpec`:** added `reversible: bool = True`. This is additive and backward compatible (V12.3 21/21 re-run).
- **V12.2 defect found and fixed:** unreliable-workflow inferences used the *success* rate as their consistency factor, so a consistently failing workflow (rate ≈ 0) could never be promoted. Consistency is now the failure rate for unreliable workflows. The V12.2 test now asserts promotion and retrieval of failure patterns (25/25).

## 5. Limitations

- Detectors are deterministic rules over existing signals, not open-ended planning.
- Suggestions are delivered to an inbox. Spoken delivery and production wiring belong to the unified-OS phase.
