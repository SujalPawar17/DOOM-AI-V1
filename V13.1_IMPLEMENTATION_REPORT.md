## 2. Implementation

- **`core/v13/cognitive_os_rollout.py`:** `CognitiveOSRollout`.
  - `DOOM_COGNITIVE_OS` = `off` (default) or `on`.
  - Lazy, thread-safe, single-instance initialization (reuses the V12 `get_doom_os()` singleton).
  - States: `NOT_INITIALIZED`, `READY`, `DEGRADED`, `SHUT_DOWN`.
  - **Initialization failure** → DEGRADED → safe fallback to the V8 core for that request. Nothing ran in DoomOS, so no duplication is possible. Re-initialization is attempted at most once per 60 s backoff.
  - **Failure during a DoomOS request** → a truthful safe message, **never re-run on V8** (the request may already have acted).
  - DoomOS is built without a speak callable, so the caller speaks exactly once.
  - Shutdown is registered once with `atexit`; `restart()` is available; `status()` reports mode, state, init latency and per-route counts.
  - Never starts the DoomOS runtime or monitor (no duplicate monitor).
- **`core/commands.py`:** the opt-in branch now goes through the rollout controller. The `off` path is the same V8 call, factored into `_v8_process`.
- **`core/v12/doom_os.py`:** additive `reset_doom_os()` so a restart builds a fresh instance.

## 4. Default-on decision: NOT enabled — exact blocker

Turning the unified OS on by default would leave **approval-required actions without a trusted approval channel**:

1. Production approvals happen in the dashboard's authenticated V8 ASK session (unlock + CSRF), which claims V8 pending plans for the **ASK session identity**.
2. DoomOS stores its pending routes against `DOOM_OWNER_ID`/`DOOM_SESSION_ID` and exposes approval only through the `DoomOS.approve()` API. The dashboard does not call it, and the identities differ.
3. Voice and text approval is intentionally impossible (prompt-injection and bystander safety).

**Required before default-on (future work):**
- Bridge dashboard ASK-session approvals to DoomOS pending routes, with identity alignment between the ASK session and DoomOS sessions.
- A supervised live trial.

Until then, `DOOM_COGNITIVE_OS=1` remains an explicit opt-in. With it on, approval-required requests are held safely (nothing executes) but can only be approved programmatically.
